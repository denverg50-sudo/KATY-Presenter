# Bible Verses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let operators look up, display and schedule Bible passages from built-in public-domain Bibles and from Bible files they import.

**Architecture:** Every Bible becomes one compact JSON (`Bible`) stored in the library. Parsing happens in a Node worker thread in the main process. Lookups and searches run in the main process against Bibles loaded lazily, and the renderer gets passages over IPC. Songs and scripture share one `Presentable` model in the renderer store, so the slide grid, live control, service list and output all treat them alike. `SlideRenderer` gains an optional footer and inline verse numbers.

**Tech Stack:** Electron 45, React 19, TypeScript, Zustand, Vitest, `saxes` (streaming XML), `sql.js` (WASM SQLite, OpenLP DB import only), `tsx` (dev script runner), electron-vite `?nodeWorker` imports.

**Spec:** `docs/superpowers/specs/2026-11-13-bibles-design.md`

## Global Constraints

- No copyrighted Bible text in the repo, installer or CI artifacts. Fixtures are invented or public-domain snippets of a few verses.
- Offline only. Data lives under `<userData>/library/bibles/` and is included in backup/restore.
- The UI reaches Electron only through `window.api` (`Api` in `src/shared/types.ts`).
- No native Node modules (Windows and Mac CI builds).
- Old services (`items: [{ id, songId }]`) keep loading. A missing `kind` means `'song'`.
- 66-book Protestant canon. Other books are skipped and listed in the import summary.
- Typing a reference updates the preview within ~100 ms. Import never freezes the window.
- npm on this machine needs `NODE_EXTRA_CA_CERTS=<keychain pem>` (Netskope). The sandbox blocks the registry.

## Review Focus

1. A reference past the end of a chapter or book (`John 3:99`, `Jude 2`, `Obadiah 1:30`) gives a clear message ("John 3 has 36 verses"), not empty slides. Tested in Task 2.
2. Book-name variants found in real files (`Psalm`/`Psalms`, `Song of Solomon`/`Song of Songs`/`Canticles`, `I John`/`1 John`/`1John`, `Revelation of John`) map to the right book. Tested in Task 1.
3. ISO-8859-1 or BOM-prefixed files with curly quotes and accented characters decode correctly (`“`, `é`). Tested in Task 3.
4. An imported Bible missing a whole book or chapter: lookup says "NIV doesn't contain Tobit/that chapter", and the import summary lists the missing books. Tested in Tasks 2 and 3.
5. A service item whose Bible was deleted renders as a "Bible not installed: pick a translation" placeholder and doesn't crash Next/Back. Tested in Task 8.

**Files:**

**Interfaces:**
- Consumes: Tasks 2–4.
- Produces `class BibleStore`:
  - `constructor(libraryDir: string, builtInDir: string)`: imports live in `<libraryDir>/bibles/<id>.json`. Built-ins are `<builtInDir>/<id>.json.gz` (ids `kjv`, `asv`, `web`, `bsb`). Abbreviation renames for built-ins go in `<libraryDir>/bibles/overrides.json` (`{ [id]: abbrev }`).
  - `list(): Promise<BibleMeta[]>`: built-ins first, then imports by name. Counts are cached in each import file's top-level `meta`, so the full text isn't loaded.
  - `passage(bibleId: string, refText: string): Promise<Passage | { error: string }>`
  - `search(bibleId: string, query: string): Promise<PassageVerse[]>`
  - `prepareImport(paths: string[]): Promise<ImportPreview | { error: string }>`, where `interface ImportPreview { token: string; name: string; abbrev: string; source: string; bookCount: number; chapterCount: number; verseCount: number; skipped: string[]; replaceCandidate: BibleMeta | null }`. It parses in the worker and holds the result in memory under `token`. `replaceCandidate` is an existing non-built-in Bible with the same abbreviation (case-insensitive).
  - `commitImport(token: string, opts: { name: string; abbrev: string; replaceId: string | null }): Promise<BibleMeta>`: with `replaceId` it keeps that id.
  - `update(id: string, patch: { name?: string; abbrev?: string }): Promise<BibleMeta>`
  - `remove(id: string): Promise<void>`: built-ins throw `'Built-in Bibles can’t be deleted'`.
  - Lazily loads Bibles and keeps an LRU of 3 in memory.
- `import-worker.ts`: receives `{ paths }`, replies `{ ok: ParsedBible } | { error }`. It detects the format (two `.csv` → CSV; one `.csv` → error `'OpenLP CSV needs both the books file and the verses file'`), then dispatches to the parsers. An unknown format gets `"This doesn't look like a Bible file. Supported: Zefania, OpenSong, OSIS, USFX, OpenLP (.sqlite or CSV)."`. In `store.ts`, import it as `import createWorker from './import-worker?nodeWorker'`, with a direct-call fallback when `process.env.VITEST` is set.
